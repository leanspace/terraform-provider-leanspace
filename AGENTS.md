# terraform-provider-leanspace — Agent Instructions

Terraform provider for the Leanspace APIs, built on `terraform-plugin-sdk/v2`. Resources mirror the
backend APIs closely: field names are the snake_case version of the API fields, and the backend
repositories (e.g. `backend/metrics-repository`) are the source of truth for types and constraints.

## Build, check, run

| Task                                   | Command                                                         |
| -------------------------------------- | --------------------------------------------------------------- |
| Build                                  | `go build ./...`                                                |
| Vet / format                           | `go vet ./...` / `gofmt -l .`                                   |
| Install locally for `terraform` to use | `make install` (version from `VERSION`, default in `Makefile`)  |
| Generate docs                          | `go generate` (runs `tfplugindocs`)                             |
| Run against a tenant                   | `cd testing && terraform init && terraform apply --auto-approve` |

There are no Go unit tests; behaviour is checked by the PR workflow (`.github/workflows/test-on-develop.yml`),
which applies `testing/main.tf`, re-applies it and expects **no changes**, then destroys everything.
Any drift between what `FromMap` sends and what `ToMap` reads back fails the PR.

## Architecture

- `provider/generic_resource.go`, `generic_data_source.go`, `generic_client.go` implement CRUD once for
  every resource. A resource only declares a `provider.DataSourceType` and its data model.
- `services/<service>/<resource>/` — one folder per resource:
  - `main.go` — the `DataSourceType` (`ResourceIdentifier`, API `Path`, `Schema`, `FilterSchema`).
  - `schemas.go` — the Terraform schema (what users write in HCL).
  - `models.go` — Go structs matching the API JSON.
  - `parsers.go` — `ToMap()` (struct → Terraform state, on read) and `FromMap()` (config → struct,
    on create/update). `FromMap` is always called on a fresh `new(T)`.
  - `validation.go` (optional) — `Validate(map[string]any) error`, called before `FromMap` on create/update.
  - `requests.go` (optional) — custom create/update/read hooks (see interfaces in `provider/parser_mapping.go`).
- `services/importer.go` — every resource must be subscribed here (`<pkg>.<Name>DataType.Subscribe()`).
- `helper/general_objects/` — shared schemas/models/parsers (definition attributes, tags, pagination).
- `helper/validation.go` — `Validators` DSL (`If`, `Equals`, `IsSet`, `IsEmpty`, `Equivalence`, ...).

Updates send the whole model (PUT), so any API field missing from the model is reset on update.

## Conventions

- **Optional nested block**: `TypeList` + `MaxItems: 1` + `Elem: &schema.Resource{...}`, pointer in the model.
  - `ToMap`: only `if x != nil { m["x"] = []map[string]any{x.ToMap()} }` — no `else`.
  - `FromMap`: `if len(m["x"].([]any)) > 0 && m["x"].([]any)[0] != nil { v.X = new(X); v.X.FromMap(...) }`.
- **Nullable number where 0 is meaningful**: `TypeList` + `MaxItems: 1` + `Elem: &schema.Schema{Type: schema.TypeFloat}`,
  `*float64` in the model (HCL: `lower_limit = [0]`). See `services/resources/resources`.
  Plain `TypeFloat` + `omitempty` treats 0 as unset.
- **Lists of primitives**: `make([]T, len(list))` then assign by index (see `services/dashboard/dashboards/parsers.go`).
- **Lists of blocks / tags**: `helper.ParseToMaps` / `helper.ParseFromMaps`.
- **Enums**: `validation.StringInSlice(values, false)` with `helper.AllowedValuesToDescription(values)` as description.
- **Type-dependent fields**: express rules with `helper.Validators` in `validation.go` (see `services/asset/properties`).
- Write a `Description` for every non-obvious field: docs are generated from them.

## Adding or changing a resource

1. Model, schema, parsers (and validation) under `services/<service>/<resource>/`; subscribe in `services/importer.go`.
2. Add `examples/resources/<resource_identifier>.tf` and `examples/data_sources/<resource_identifier>.tf`
   (the PR workflow fails without them).
3. Add/update `testing/<service>/<resource>/main.tf` and reference it from `testing/main.tf`.
   Test resource names start with `Terraform`.
4. Do **not** edit `docs/`: it is regenerated by the release workflow ("Update docs" commits).

## Git

- Commit messages and branch names start with the JIRA key (e.g. `LIS-28 Add calibration schema to metrics`,
  branch `LIS-28-terraform-support-metrics-calibrations`). Use `<PROJECT>-000` when there is no ticket.
